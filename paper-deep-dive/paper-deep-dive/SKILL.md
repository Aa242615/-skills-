# 论文深度解析与汇报材料生成

把一篇论文拆成五份互补的产物：**读得懂**（精读）、**讲得出**（术语 + PPT）、**定位得准**（引用脉络）、**走得下去**（idea）。

这个 skill 存在的理由：论文汇报真正的失败模式不是"做得不够多"，而是**把论文读错了然后做了 20 页 PPT**。所以流程的重心在"先核对再生成"，而不是"多产出"。

## 默认语言与交付格式

- 用户没有指定语言时，正文、PPT、讲稿和 Word 文档默认使用中文；论文标题、作者、模型名、数据集名、公式、DOI、arXiv ID 和代码命令保留原文。
- A、B、D、E 以及新增的 F《PPT 逐页讲稿》最终交付为 `.docx`，不要把 `.md` 作为用户的主要交付文件。Markdown 可以作为内部中间稿，但交付前要转成结构清楚、可直接阅读的 Word 文档。
- Word 文档要比 PPT 更详细：先给一句话结论，再解释背景、方法、证据、限制和可复现性；首次出现的术语写成「English（中文）」并给出易懂解释。
- Word 段落使用原生项目符号或编号样式、左缩进和悬挂缩进；不要把 `•`、`1、` 等字符手工拼进正文。每个并列段落都必须有清楚的标识和层级。

## 第一步：收齐参数（缺哪项就问，不要替用户假设）

一次问全，不要挤牙膏式地来回问：

| 参数 | 为什么必须问 |
|---|---|
| 论文来源 | 文件路径 / 标题 / DOI / arXiv ID。**给的是标题时先检索确认唯一命中再继续**——同名论文很多，检索错的代价是整份材料作废 |
| 汇报场合 | 组会文献汇报 / 开题 / 课程 pre / 论文答辩。决定详略与语气。**PPT 版式与风格不论场合一律遵循样例模板 `references/group-meeting-template.md`（源自 `references/group-meeting-sample.pptx`），风格、字体、格式与样例保持一致** |
| 听众 | 同方向研究生？跨方向？导师在场？决定术语需要解释到什么程度 |
| 时长与页数上限 | 15 min 和 30 min 的 deck 密度差一倍。页数上限比"讲清楚"更能约束排版 |
| 语言 | 默认中文；术语、标题、作者、模型名、数据集名和公式保留英文原词，除非用户另有要求 |
| 输出目录 | 明确到绝对路径，避免文件散落在临时目录里；文字材料默认输出 `.docx` |
| idea 的交付形态 | 默认输出详细的 `05_idea.docx`；用户明确说"每个 idea 单独一份"时按 `references/idea-docx.md` 拆成多个 `.docx` 或单页 `.pptx` |
| 检索工具 | 有没有 Undermind 账号。有则让用户自己跑一轮检索式并把结果贴回来，同时并行用免费源交叉验证（见 `references/literature-search.md`） |

**"第一次汇报"这类描述要追问。** 它通常意味着用户自己也是新手，那么"局限与我的思考"这一页尤其重要（这是导师最会问的地方），而方法细节可以适当压缩。

## 第二步：通读，然后停下来确认

用 `pdf` skill 完整读取全文——**正文 + 公式 + 图表 + 参考文献 + 附录**。只读摘要就动手是本 skill 要避免的头号错误：论文的实际贡献经常和摘要写的不是一回事，消融实验里的结论也常常被摘要有意淡化。

读完后**先只交付一页纸大纲**：论文一句话概括 + PPT 目录 + 五份产物的文件名。让用户确认后再生成正式产物。

这一步看着像浪费时间，实际上是最省时间的一步：误解在这时候被发现，改的是三行字；误解在 PPT 做完后发现，改的是全部。

## 第三步：五份产物

详细的写作模板见 `references/analysis-templates.md`（产物 A、B、E 的逐项清单）。

- **产物 A《论文精读》** → `01_论文精读.docx`
- **产物 B《技术与术语》** → `02_技术与术语.docx`
- **产物 C《汇报 PPT》** → `03_汇报.pptx`（任何汇报场合，先读 `references/group-meeting-template.md` 和 `references/ppt-reference-notes.md`；主基准是 `references/group-meeting-sample.pptx`，其他样板只用于吸收排版经验）
- **产物 D《相关工作与引用脉络》** → `04_相关工作.docx`（检索源、API、防幻觉规则见 `references/literature-search.md`）
- **产物 E《可延伸的 Idea》** → `05_idea.docx`
- **产物 F《PPT 逐页讲稿》** → `06_PPT讲稿.docx`

文字材料必须详细到用户可以直接阅读和汇报：每个主要结论都要说明依据、含义、局限和下一步；不要为了省页数把完整解释压缩成 PPT 式短句。

**产物 F 的逐页讲稿规则。** 每一页 PPT 都必须有对应讲稿，不能只生成一段总览或重复幻灯片文字。每页讲稿至少包括：本页要回答的问题、用通俗语言解释页面含义、图表/公式/流程的读法、论文证据来源、一个必要时可使用的生活化类比或具体例子、与下一页的过渡。讲稿要像人在组会上解释，而不是朗读标题；先讲直观场景，再引入英文术语和数字。明确区分“论文已经证明的事实”“根据图表做出的解释”和“汇报者推断/后续想法”。

讲稿中的例子必须服务于理解，不能引入论文没有支持的新事实。涉及模型、数据集、指标、图号或数字时沿用 PPT 和论文中的来源；例子可以使用“餐馆套餐、仓库取货、城市道路、专家团队、图片压缩”等类比，但必须明确它们只是帮助理解的类比。默认建议每页讲 40–90 秒，方法、实验和局限页可以更长。

## 硬性规则

这几条是产物能不能拿出去的底线，比任何格式要求都重要：

**不编造文献。** 引用脉络是最容易翻车的部分——LLM 会流畅地生成不存在的论文标题、作者和年份，而且看起来极其可信。规则是：每条引用必须有可核验的链接（DOI / arXiv ID / 会议页）；**查不到的宁可不写**；检索不到后续引用就直说"暂未检索到 / 该文较新"，不要凑数凑满 5 篇。用户宁可要 2 条真的，也不要 10 条编的。

**事实与解读分开。** 论文原文写了什么是一回事，你怎么理解是另一回事。用户拿这份材料去汇报时，导师会追问"这是作者说的还是你说的"。所以推测处一律标注「推断」。

**数值必须有出处。** 每个指标、每个结论都标注章节号 / 图号 / 表号 / 公式号。这样做不只是严谨——它让用户在被追问时能立刻翻到原文那一页。

**术语写成「英文（中文）」。** 技术术语的中文译名极不统一（attention 有译"注意力"也有译"关注"），保留英文原词才能让用户自己去检索。首次出现处给中文解释，之后直接用英文。

**每一页都要有中南大学校徽。** PPT 的所有页面——包括封面——都必须放中南大学校徽（素材 `references/assets/csu-logo.png`）。内页统一放在右上角（L=10.42" T=0.18" W=2.38" H=0.66"），封面右上角同样位置放一枚，确保从第一页翻到最后一页校徽都在、位置一致、不被其他元素遮挡。

**论文配图必须完整，图外文字必须清理。** 从论文取图时，必须保留当前结论需要的坐标轴、刻度、曲线、柱子、子图和必要图例；删除论文页眉、页脚、页码、Figure 编号、Figure caption、正文段落和无关作者信息。图内数据不能被截断，图外说明文字不要带进 PPT。优先用 `scripts/extract_pdf.py figures` 抽原图；抽不到时用 `pages --dpi 300` 渲染整页再裁剪，裁剪后逐图目视确认。

**交付前三查排版。** 产物 C 完成后必须过三轮检查才算完：(1) 跑 `scripts/check_deck.py`，ERROR 清零、WARNING 逐条确认；(2) 打开 PPT 完整目视一遍，专查整体结构、文本溢出、元素重叠、图片是否被裁、校徽是否每页都在；(3) 再逐页对照检查清单核对字体字号统一、中英对齐、图注不压图、备注完整。任何一轮发现问题都改完产物后重跑全部轮次。

**每完成一份产物就说一声。** 六份材料一次性交付，用户面对的是六个不知从何看起的文件；逐个交付，用户能在过程中纠偏。

**文字材料默认中文 Word 交付。** A、B、D、E 必须交付为 `.docx`，结构包含标题、摘要式结论、分级小标题、原生项目符号、表格、引用链接和“作者事实 / 我的解读 / 尚未核验”标识。除非用户明确要求，不能只交 Markdown。

**PPT 必须白底、图文分区、字号足够大。** 页面使用白色背景和深色文字，允许标题使用样例的深红色；禁止“文字放在色块上”或“文字下方铺一大片色块”。每页优先采用左文右图、左图右文、上文下图或上图下文四种分区，图和文字各占约一半，边界留出安全间距，不要让文字、图片、图注互相穿插。正文优先 22–24pt，标题 30pt 左右；空间不够时拆页或缩短内容，不要把字号压小。

**PPT 的结构标签与目录规则。** 不生成“Outline”“目录”“汇报大纲”“Contents”或任何单独的 PPT 总览页。封面之后直接进入第一个内容页，汇报结构通过页序、speaker notes 和每页的小型英文 section label 体现。每个内容页必须有一个简短的 section label，优先从 `Background`、`Motivation`、`Problem`、`Related Work`、`Method`、`Design`、`System`、`Implementation`、`Evaluation`、`Results`、`Ablation`、`Limitations`、`Takeaways`、`Q&A` 中选择。section label 只用于定位当前模块，不写成句子、不重复页面主标题；页面主标题使用中文主题句。除非用户明确要求，不能用目录页替代内容页。

**PPT 模板复用规则（最高优先级）。** 生成 PPT 时首先使用用户提供的完整模板文件，当前全局资源是 `references/group-meeting-template.pptx`，来源为 `skills补充/20260525_组会(1).pptx`。优先复制模板中已有的“标题 + 正文 + 下方图片”页面，再替换文字和图片；模板已有的标题框、正文框、横线、页边距、字体、颜色、行距、缩进和段落级别全部保留。只有模板确实无法承载内容时才新建页面，新建页面也必须复制模板的 XML 样式。PPT 使用白底和深色文字，分点不得放在色块、卡片、圆角矩形、渐变框或任何彩色背景上。不能为了填空添加装饰条、侧边色带或 AI 风格的信息卡片。

**PPT 字体与分点规则。** 标题、小标题、正文、图上文字和图注必须从模板样例页面复制格式，不能自行另设字体、字号、颜色、行距、首行缩进、悬挂缩进或对齐方式。正文使用模板的段落层级和 PowerPoint 原生项目符号：如果一个大点下面有多个小点，一级大点使用方块项目符号（如 `■`），二级解释使用箭头项目符号（如 `→`），并保持模板缩进；只有并列的小点时使用小箭头，不使用方块。不要手写“1、2、3”，不要用彩色形状伪造项目符号。每页正文通常约 3 个内容点，一级大点最多 2–3 个，每个大点下只保留必要的 1–2 个小点；正文不能小于模板正文的字号。

**PPT 可理解性规则。** 每页只回答一个问题，页面标题必须是听众能直接理解的中文句子，例如“历史状态太大，不能一直放在 GPU”或“先保存更小的中间状态，再恢复 KV”。第一次出现专业术语时先用普通话解释，再写英文术语；删掉不能帮助听众理解论文的细节。PPT 不是论文缩印版，优先保留问题、核心想法、关键证据和限制。每页正文只写 2–3 个短点，字多时删内容，不缩小字号。speaker notes 承担补充解释，页面本身保持简洁。

**PPT 图文位置与截图规则。** 默认采用“上方短文字、下方大图片”的模板页面。除非模板已有左右布局且确实更清楚，否则不把文字和图片挤在两列。论文截图必须先清理：删除页眉、页脚、页码、Figure 编号、Figure caption、正文段落、无关表格和无关作者信息；图表内部保留理解数据所必需的坐标轴和必要图例，图外不再添加图名或说明。每次裁剪后人工查看原图和裁剪图，确认坐标轴、刻度、曲线、柱子、箭头和子图完整。抽不到原图时使用 300 DPI 页面渲染后裁剪；截图必须干净，不能把论文页面整页缩小塞进 PPT。

**PPT 整页调整规则。** 生成后必须重新审视每一页的整体布局。每页正文通常保留约 3 个简单易懂的内容点，字多时先删掉次要信息或拆页。页面太空时，先扩大下方图片并让它占据图片区的主要空间，再在模板允许范围内调整正文；图片必须保持比例，必要时可裁掉无关白边或无关子图，但不能裁掉当前结论需要的数据。检查标题、正文、图片、校徽和页边距的视觉重心，不能让下半页长期留下大块无意义空白。任何元素都不能重叠、越界或压住图片。禁止“每一点一个色块”的布局，禁止在文字下铺色块。每页都要看起来像同一个模板生成的内容页，而不是自动生成的卡片集合。

**PPT 的段落必须有层级标识和缩进。** 使用 PowerPoint 原生项目符号和两级以内的缩进；不要使用“1、2、3”或把多个句子塞进一段。每个要点只表达一个意思，首层要点加粗，二层要点解释证据或例子。

## 已有汇报的迭代修订与交付清理

当用户要求修改已有的多次汇报 PPT 时，按下面的闭环执行，而不是只调整几个文本框：

1. **先盘点版本和范围。** 列出目标汇报目录中的 PPT、Word、论文 PDF、截图目录、渲染目录、脚本和检查报告，区分“最终交付版”和“历史/中间版”。第一次汇报、用户指定的样例 PPT 和未在范围内的正式材料不得被改写。
2. **真实样例优先于泛化规则。** 先读取用户实际样例 PPT 的页面、主题和 XML。样例中的标题位置、正文字号、颜色、行距、缩进、页码、校徽和项目符号是最终依据；技能中的 `■`、`→` 等只表示层级概念，不能替代样例的真实符号。
3. **原生项目符号必须复制 XML。** 若样例项目符号由 Wingdings、特殊字符或主题级 XML 实现，复制样例段落的 `<a:pPr>`、`<a:buFont>`、`<a:buChar>`、`<a:buClr>`、缩进和行距，不能用 Unicode 方块、文本前缀或绘制形状替代。修改后逐段比较字体、字形、颜色、缩进和行距；记录通过的段落数量。
4. **先改内容证据，再改版面。** 论文截图必须来自论文 PDF 的原图或高 DPI 页面渲染。每张截图保留当前结论所需的轴、刻度、图例、箭头和子图，清除页眉、页脚、页码、图注、正文和无关区域。截图裁剪后同时查看原页、裁剪图和放入 PPT 后的实际效果；禁止用重绘的假图代替论文证据。
5. **按页解决“空”和“挤”。** 空旷页面先扩大有效论文图、裁除无关白边、合并有直接证据关系的图，并补充一两条“读图结论/证据来源”；不得用装饰色块、卡片、重复标题或无依据文字填空。拥挤页面先删次要句、拆页或缩短句子，最后才在不低于样例字号的前提下调整尺寸。图片始终保持比例。
6. **必须实际渲染后验收。** 不能只依赖 `python-pptx` 的 XML 检查。每个目标 PPT 都要导出 PDF/PNG 或用可用的 Office/WPS 渲染逐页查看；检查标题、正文、图片、图注、校徽、页码、文字溢出、图片裁切、重叠、清晰度和页面视觉重心。任何一页发现问题，修改后重新跑完整检查，不接受“只改这一页所以不用重检”。
7. **保存可恢复的原稿，再覆盖或另存。** 批量替换前建立带路径和哈希的原稿备份。若用户在处理期间修改了原文件，不覆盖其新改动，改为同目录生成明确的“排版优化版”，并在交付说明中指出。
8. **交付前清理目录。** 逐个汇报目录只保留论文 PDF、正式 Word 材料和最终 PPT；删除或移入回收站旧版本 PPT、旧 Word、渲染 PNG/PDF、截图缓存、脚本、`__pycache__`、检查报告和临时素材。清理前检查正式 Office 文件可打开且没有依赖被删除的外部媒体，记录保留文件哈希；第一次汇报和样例目录不参与清理。

这套闭环的最低验收记录应包含：目标文件清单、页数、实际渲染页数、文本溢出数、项目符号 XML 一致性、每页备注/校徽检查结果、论文截图来源，以及清理后保留的正式文件清单。

## 绘图技能路由

项目 `skills/` 中已部署以下绘图技能，按图形类型选择，生成的图统一保存到当前任务的 `figures/` 或交付目录：

- `figure-generation`：有数值、坐标轴或方法对比时，生成 300 DPI PNG 和矢量 PDF，并保留可复现脚本。
- `academic-plotting`：论文结果图、消融图、训练曲线、热图和统计图；优先使用色盲友好配色。
- `figure-spec`：架构图、方法总览和流程图的首选，使用确定性 JSON → SVG，便于编辑、复核和后续放入 PPT。
- `mermaid-diagram`：快速绘制简单流程、时序和关系图；需要正式交付时再转成可编辑 SVG 或高分辨率图片。

文字密集或要求精确标签的学术图，不要默认使用生成式图片。生成式示意图只能用于定性概念图，并且必须逐项核对文字、箭头方向、模块数量和图例。

## 最后：交付前自检（产物 C 必须三轮检查）

**第一轮：脚本检查。** 跑 `scripts/check_deck.py`，ERROR 必须清零，WARNING 逐条确认过；它自动查封面要素、字号下限、东亚字体、图片分辨率、讲稿备注、文本溢出、元素重叠、**每页校徽是否存在**、图片是否越出页面。

**第二轮：整体目视。** 打开 PPT 完整翻一遍，专查脚本查不出的问题：整体节奏、页面拥挤度、文本框是否压图、图片是否被页边裁掉、校徽是否每一页都在且位置统一、封面信息是否齐全。

**第三轮：逐页对照清单。** 一页一页对照下面清单核对，全部通过才算完成：

- [ ] 封面含**英文原题 + 全部作者 + 会议/期刊全称 + 年份**（用户明确点名要求的，最容易漏）
- [ ] **每一页（含封面）都有中南大学校徽**，位置统一、无遮挡、不变形
- [ ] 每个数值/结论都能追到章节、图号、表号或公式号
- [ ] PPT 无文本溢出、无元素重叠、无低清图片；字体字号全文统一
- [ ] 版式以 `references/group-meeting-sample.pptx` 为主，并吸收 `references/ppt-reference-notes.md` 中其他样板的优点：白底、无大色块、标题约 30pt、正文 22–24pt、标题 Times New Roman + 正文 Arial（中文微软雅黑）
- [ ] 每页采用清楚的图文分区，正文约 2–3 个简单内容点；图片在不变形、不丢数据的前提下尽量放大；不存在文字与图片交叉、下半页大片空缺或文字压在色块上的情况
- [ ] 有上下级关系时一级大点使用方块、二级解释使用箭头；没有上下级关系时使用小箭头；所有项目符号有原生缩进和清晰层级，没有手工拼接的“1、2、3”列表
- [ ] 标题栏**无副题总结小字**；图片**完整未裁切**（含当前结论需要的坐标轴/图例/子图）；论文页眉、页脚、Figure 编号和图注已从图外清掉
- [ ] 中英混排字体对齐：行高统一、基线对齐、同类文字字号字体一致（见 `references/group-meeting-template.md`）
- [ ] 所有引用文献都有可点击链接，且真实存在
- [ ] 术语表覆盖正文出现的所有专业名词
- [ ] 每页都有讲稿备注（speaker notes）
- [ ] 文件都在输出目录里，文件名与大纲确认页一致

三轮中任何一轮发现问题，修改产物后**从头重跑全部三轮**，不能用"只改这一处"代替。核对结果逐条贴给用户。

## 工具

- `scripts/extract_pdf.py` — 抽正文（带页码）、导出内嵌图片、按指定 dpi 渲染页面。做 PPT 配图时用它拿原图，比截图清楚得多。
- `scripts/check_deck.py` — 检查 `.pptx` 的封面要素、字号、图片分辨率、讲稿备注、文本溢出、元素重叠、**每页校徽、图片越界**。

```bash
python scripts/extract_pdf.py text   paper.pdf                 # 抽正文
python scripts/extract_pdf.py figures paper.pdf -o figs/       # 抽内嵌图片
python scripts/extract_pdf.py pages  paper.pdf -o pages/ --dpi 300 --pages 3-7
python scripts/check_deck.py deck.pptx --report check.md
```
