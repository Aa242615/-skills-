# 每个 idea 单独成文：Word 与单页 PPT 的规范

默认情况下产物 E 是**合并的一个 `05_idea.md`**（模板见 `analysis-templates.md`）。只有当用户明确说"每个 idea 单独一份"时，才按下面的规范拆分。

**这条规矩值得坚持**：三个 idea 拆成三份 docx，用户要开三次、来回对照，反而不如一份 .md 好读。用户明确要求时才拆。拆分前先问一句交付形态是什么：

| 用户说法 | 交付 |
|---|---|
| "给我几个 idea" / "还能怎么改进" | `05_idea.md`，合并一份 |
| "每个 idea 单独一份文档" | `idea-01-<slug>.docx`、`idea-02-<slug>.docx` … |
| "每个 idea 做一页 PPT" | `idea-01-<slug>.pptx` … 或合并成一个 `05_idea.pptx` |
| "汇报末尾要讲我的思考" | 从产物 E 挑最扎实的 2–3 条，进主 deck 第 17 页 |

---

## 一、Word 版（`.docx`）

用 `docx` skill 生成。每份控制在 **2 页以内**，结构固定：

```markdown
# Idea 01：<一句话标题>

**一句话**：（这条 idea 想让什么变得更好，用一个具体指标或场景说清）

## 从哪来
论文第 X 节指出 / 图 Y 里我们看到……（必须锚定到论文的具体位置，这是"我认真读了"的证据）

## 为什么现在还是空白
（要具体。反面例子："相关研究较少"；正面例子："现有工作都在单模态上验证，
跨模态方向未见公开报道，检索于 <日期>，源为 OpenAlex"）

## 具体怎么做
1. ……（3–5 步，细到"下周就能开工"）
2. ……
3. ……

## 预期收益与风险
- 收益：（做到什么程度算成功，用什么指标衡量）
- 风险：（最可能失败在哪一步）
- **最小验证实验**：先做一个什么实验就知道这条路通不通（通常是一周内能跑完的）

## 需要的资源
数据 / 算力 / 代码 baseline / 人力

## 相关文献
| 题名 | 年份 | 链接 | 与本文的关系 |
```

**排版要求**：正文 11–12pt，标题用内置 Heading 样式（便于生成目录），代码与公式用等宽字体，引用文献编号统一。

## 二、单页 PPT 版

**一页讲一个 idea**，不要拆成多页——一页讲不完的 idea 在汇报场合本来也讲不完。

版式（16:9，与主 deck 同一套主色和字体）：

```
┌──────────────────────────────────────────────┐
│  Idea 01：<一句话标题>                  [页码] │
├───────────────────────┬──────────────────────┤
│  ▪ 从哪来              │                      │
│  ▪ 为什么是空白        │   [示意图 / 流程图]   │
│  ▪ 怎么做（3–5 步）    │   占页面 40–45% 宽    │
│  ▪ 预期收益 / 风险     │                      │
│  ▪ 最小验证实验        │                      │
├───────────────────────┴──────────────────────┤
│  来源：本文第 X 节 · 支撑文献 [1][2]           │
└──────────────────────────────────────────────┘
```

- 左栏文字**不超过 8 行**，每行 ≤ 22 个汉字（与主 deck 同一套限制）。
- 示意图用 matplotlib / Mermaid 现画，不要用论文原图——原图讲的是论文的方法，不是你的 idea。
- 每页都要有讲稿备注，3–5 句。
- 生成后同样跑一遍 `scripts/check_deck.py`。

## 三、Idea 的质量门槛

生成 idea 时按下表从易到难找，**先保证有 3 条扎实的**，再考虑凑数：

| 来源 | 说明 | 难度 |
|---|---|---|
| 补论文的遗留问题 | 作者在 Limitations 里自己承认的 | 低 |
| 换设定 | 换数据集 / 模态 / 规模 / 评测指标，看结论还成不成立 | 低 |
| 方法拼接 | 把本文模块和另一条技术线结合 | 中 |
| 质疑假设 | 论文某处默认成立的前提，去掉会怎样 | 高（最有价值） |
| 应用落地 | 用在本领域的实际问题上 | 中 |

每条必须回答"**为什么现在做是时机**"——是算力够了、数据开源了，还是新方法刚出现使得它变得可行。**答不上来的想法大概率别人早试过了。**

## 四、反面示例

> **Idea：把 Transformer 用到更多任务上**
>
> 现在 Transformer 很火，可以尝试把它用到更多任务上，应该会有不错的效果。

问题：没说清从哪来、没说为什么是空白、没法执行、没有衡量标准、没有任何文献支撑。这种 idea 汇报时会被一句话问倒：「那 XX 那篇不是已经做了吗？」

改法：把"更多任务"替换成一个**具体的任务 + 具体的空白 + 具体的指标**，并给出最小验证实验。
